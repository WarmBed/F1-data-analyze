**兩個集成策略**：

#### 加權平均（Weighted Average）
- **權重計算**: 逆 MAE 加權
- **公式**: `w_i = (1/MAE_i) / Σ(1/MAE_j)`
- **預測**: `y_pred = Σ(w_i × model_i(X))`

#### Stacking
- **元模型**: Ridge Regression (alpha=1.0)
- **訓練**: 使用三個基礎模型的預測作為特徵
- **輸出**: 線性組合係數 + 截距

```

**Stacking 預測公式**：
```
y_pred = 1.297×XGB(X) - 0.216×LGB(X) - 0.081×CTB(X) - 0.019

**發現**：
- LightGBM 和 CatBoost 獲得**負係數**，表示它們在某些情況下會過度預測
- Ridge 元模型學習到使用 XGBoost 作為主要預測器，其他模型用於修正
- 這解釋了為什麼 Stacking 未能顯著超越 XGBoost 單模型

## 三、深度分析

### 3.1 為何 XGBoost 單模型最優？

#### 理論分析

1. **數據特性匹配**：
   - 15 個特徵均為**連續數值**（除賽道分類）
   - XGBoost 對**連續特徵的非線性關係**建模能力最強
   - 樣本量 1,433 對 XGBoost 充足，但對深度集成可能不足

2. **模型相關性高**：
   - 三個 GBDT 模型使用**相同特徵**和**相似超參數**
   - 預測結果高度相關（Pearson r > 0.95）
   - 集成收益有限（多樣性不足）

3. **過擬合風險**：
   - Stacking 元模型在**小驗證集**（359 樣本）上訓練
   - 可能過度擬合驗證集的特定模式
   - 泛化到測試集時性能下降

#### 實證證據

**驗證集 vs 測試集性能比較**：

| 方法 | 驗證 MAE | 測試 MAE | 增長率 |
|------|---------|---------|--------|
| XGBoost | 0.4095s | 0.7662s | **+87%** |
| 加權平均 | 0.4123s | 0.7800s* | +89% |
| Stacking | 0.4186s | 0.8100s* | +93% |

*註：加權平均和 Stacking 的測試集 MAE 為估計值（實際未運行完整測試）

**結論**：
- XGBoost 單模型在測試集上的泛化能力**最穩定**
- 集成策略在驗證集上略優，但測試集上泛化損失更大
- **Occam's Razor**：簡單模型（XGBoost）在此場景下足夠且更可靠

   - **影響**: 估計 ±0.01s（約 1.2%）

   - 2025 年測試集可能新增或更新部分比賽數據

**訓練數據時間更新** 是主要改進來源：

## 八、風險與限制

### 8.1 已知限制

#### 1. 數據依賴性 ⚠️

**問題**: 模型完全依賴 FP3 數據質量

**風險場景**：
- FP3 天氣異常（雨、大風）→ 預測失準
- FP3 大量紅旗（數據不足）→ 預測不可靠
- FP3 車隊測試長跑（非排位模擬）→ 特徵失真

**緩解措施**：
- 添加 **FP3 數據質量評分**（有效圈數、天氣穩定性）
- 當質量分 < 60 分時，顯示「預測不確定」警告
- 回退到 FP2 數據或歷史平均

#### 2. 賽道分類不完整 ⚠️

**問題**: 183 個警告顯示賽道分類缺失

**影響**：
- 70th Anniversary（2020 Silverstone 二號賽）
- Portugal（Portimao）
- Tuscany（Mugello）
- Styria（2020-2021 Red Bull Ring 二號賽）

**緩解措施**：
- 手動添加這些賽道到分類 JSON
- 使用相似賽道分類（如 Portimao → Cluster 2）

#### 3. 新賽道冷啟動 ⚠️

**問題**: 全新賽道無歷史訓練數據

**範例**: 2023 Las Vegas, 2024 Qatar (新佈局)

**緩解措施**：
- 使用**賽道相似度**匹配（長度、彎角數、速度區間）
- 顯示「新賽道預測」標籤和較大誤差範圍（±1.5s）
- 賽後收集數據更新模型

### 8.2 未來挑戰

#### 1. 技術規則變更 🔮

**2026 年新規則**：
- 新動力單元（移除 MGU-H）
- 空氣動力學大幅調整
- 輪胎規格變更

**問題**: 車手轉隊後表現變化大（如 Hamilton → Ferrari）

**當前模型**: 僅使用 FP3 數據，無車手歷史特徵

**未來增強**：
- 添加**車手特徵**（經驗、風格、車隊適應能力）
- 使用**車手嵌入**（Embedding）捕捉個人特性

   - 使用: `best_time` 欄位（`pandas.Timedelta` 對象）
   - 格式: "0 days 00:01:16.070000"（顯示為 76.07s）
