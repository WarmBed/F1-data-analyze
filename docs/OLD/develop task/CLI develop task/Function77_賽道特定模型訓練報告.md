# Function 77: 賽道特定模型訓練報告

## 執行摘要

**訓練日期**: 2025-11-03  
**訓練器版本**: TrackSpecificTrainer v1.0  
**訓練策略**: 每個賽道訓練獨立的 XGBoost 模型  
**最新更新**: 2025-11-03 - 墨西哥模型重訓練（2022-2024 數據）+ 2025 驗證測試

### 核心成果

- **訓練賽道**: 8/10 個原型賽道成功訓練

- **2025 年預測挑戰**：訓練數據平均 77.914s vs 2025 實際 76.730s（快 1.184s），導致趨勢驗證未達標

## 1. 設計決策總結

### 1.1 已確認的架構決策

| 項目 | 決策 | 理由 |
|------|------|------|
| **低樣本賽道** | 即使樣本少仍訓練獨立模型 | 保持一致性，避免分組複雜度 |
| **最低訓練需求** | 只要有 1 年數據（~20 樣本）即可 | 降低門檻，支援新賽道 |
| **模型更新頻率** | 每場賽事後立即重新訓練 | 保持模型最新，反映賽道變化 |
| **檔案結構** | 單一檔案存放（每賽道獨立 .pkl） | 便於單獨更新和版本控制 |
| **賽道識別** | 使用賽道名稱（`race: "Mexico"`） | 與訓練數據格式一致 |
| **特徵工程** | 保留所有特徵 + 新增歷史特徵 | 最大化模型信息量 |
| **實作優先順序** | 原型驗證（10 個主要賽道） | 快速驗證方法可行性 |
| **驗證方式** | 兩階段驗證（訓練集 + 測試集） | 全面評估模型性能 |

### 1.2 與 Function 76 的核心差異

| 比較項目 | Function 76（單一模型） | Function 77（賽道特定） |
|----------|------------------------|------------------------|
| **模型數量** | 1 個全局模型 | 29+ 個獨立模型 |
| **訓練範圍** | 所有賽道混合訓練 | 每個賽道單獨訓練 |
| **時間範圍** | 53s-128s（全賽道範圍） | 每賽道固定（如 Monaco 70-72s） |
| **模型適應性** | 預測平均值（~83s） | 精確適應賽道特性 |
| **訓練 MAE** | 0.22s（混合） | 0.009-0.016s（單賽道） |
| **測試 MAE** | 13.10s（2025 R20） | 0.190-0.973s（交叉驗證） |

## 5. 特徵工程分析

### 5.1 使用的特徵（共 21 個）

#### 基礎特徵（4 個）
- `fp3_best`: FP3 最佳圈速

#### 分段特徵（3 個）
- `fp3_sector1`: FP3 第一段最佳時間
- `fp3_sector2`: FP3 第二段最佳時間
- `fp3_sector3`: FP3 第三段最佳時間

- `track_length`: 賽道長度
- `turns_count`: 彎道數量

- `air_temp`: 氣溫

## 7. 與 Function 76 的詳細比較

### 7.1 設計哲學差異

| 方面 | Function 76 | Function 77 |
|------|-------------|-------------|
| **核心假設** | 所有賽道可用單一模型學習 | 每個賽道特性獨立 |
| **訓練策略** | 混合訓練（all-in-one） | 分離訓練（divide-and-conquer） |
| **預測範圍** | 53s-128s（全範圍） | 賽道特定（如 70-72s） |
| **模型複雜度** | 高（需學習 29 種賽道） | 低（只學習 1 種賽道） |
| **更新成本** | 高（全量重訓） | 低（單賽道更新） |

### 7.2 性能比較

| 測試場景 | Function 76 | Function 77 | 改善幅度 |
|----------|-------------|-------------|----------|
| **訓練集 MAE** | 0.22s（混合） | 0.009-0.016s（單賽道） | **93-95%** ⬆️ |
| **測試集 MAE（2025 R20）** | 13.10s | 0.398s（平均） | **96.96%** ⬆️ |
| **最佳賽道（Monaco）** | - | 0.190s | - |
| **最差賽道（Mexico）** | - | 0.973s | 仍優於 13.10s |
| **R2 分數** | 0.9386（聲稱） | 0.4094（平均） | ⚠️ 受 Mexico 影響 |

### 7.3 關鍵發現

1. **Function 76 的根本問題**：
   - 訓練數據範圍太廣（53s-128s）
   - 模型學習到的是「平均值」（~83s）
   - 無法適應特定賽道的時間範圍
   - 測試數據格式不一致導致預測失敗

2. **Function 77 的優勢**：
   - 每個賽道獨立學習，精確適應賽道特性
   - 訓練 MAE 極低（< 0.02s）
   - 測試 MAE 優秀（平均 0.398s）
   - 可即時更新單一賽道模型

3. **Function 77 的挑戰**：
   - Mexico 賽道表現異常（R2 負值）
   - 需要處理賽道名稱映射問題（Silverstone vs Great Britain）
   - 模型管理複雜度提升（29+ 個檔案）

## 8. 問題與改進建議

### 8.1 已發現問題

#### 問題 1: Mexico 賽道異常表現 ⚠️

**現象**：
- 測試 MAE: 0.973s（最高）
- 測試 R2: -2.4961（負值）

**原因分析**：
1. **賽道改建**：2022 年 Mexico 賽道修改了多個彎道
2. **高海拔影響**：2,250m 海拔導致引擎功率、輪胎表現差異大
3. **數據不一致**：2022 前後數據混合訓練導致模型混淆

**改進方案**：
```python
# 方案 A: 分年訓練
train_mexico_2018_2021(data_pre_2022)
train_mexico_2022_2024(data_post_2022)

# 方案 B: 新增高海拔特徵
features['altitude'] = 2250  # 米
features['air_density_ratio'] = 0.75  # 相對海平面

# 方案 C: 移除極端值
remove_outliers(data, threshold=3*std)
```

#### 問題 2: 賽道名稱不一致

**現象**：
- 原型賽道 `Silverstone` 找不到數據
- 原型賽道 `USA` 找不到數據

**原因**：
- JSON 數據使用國家名稱（`Great Britain`, `United States`）
- 原型清單使用賽道名稱（`Silverstone`, `USA`）

**改進方案**：
```python
TRACK_NAME_MAPPING = {
    'Silverstone': 'Great Britain',
    'USA': 'United States',
    'Dutch': 'Netherlands',
    'Abu Dhabi GP': 'Abu Dhabi',
    # ... 完整映射表
}
```

#### 問題 3: 2025 測試集驗證未完成

**原因**：
- 2025 測試數據使用 `race: 20`（編號）
- 訓練數據使用 `race: "Mexico"`（名稱）
- 無法建立映射關係

**改進方案**：
1. 建立 2025 賽曆映射表
2. 從 FastF1 API 查詢 2025 賽程
3. 手動建立 race_number → track_name 映射
