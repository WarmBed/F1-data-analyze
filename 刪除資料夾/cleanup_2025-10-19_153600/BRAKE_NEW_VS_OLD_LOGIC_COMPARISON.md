### 舊邏輯（硬編碼終點）

```python
# ❌ 舊方法：硬編碼煞車終點字典

    "China": 4775,
    "Japan": 5369,
    "Monaco": 2077,
    # ...其他賽道

```

**缺點**：
- ❌ 需要手動維護每個賽道的終點位置
- ❌ 無法自動適應賽道變化（如路緣石改變、賽道改建）
- ❌ 精度依賴人工輸入，可能存在誤差
- ❌ 新增賽道需要手動添加配置

---

### 新邏輯（加速度動態偵測）

```python
# ✅ 新方法：基於加速度最大負值自動偵測

# 步驟 1: 從最速車手全圈找參考煞車終點
reference_brake_distance, reference_max_neg_accel, brake_end_idx = \
    self._find_reference_brake_endpoint(car_data)

# 步驟 2: 其他車手在參考終點±50m 找個人煞車終點
driver_brake_distance, driver_max_neg_accel, brake_end_idx = \
    self._find_driver_brake_endpoint(car_data, reference_brake_distance)

# 步驟 3: 從終點往前找煞車起點（加速度 > -1 m/s²）
brake_start_distance, brake_start_idx = \
    self._find_brake_start_from_endpoint(car_data, brake_end_idx)
```

**優點**：
- ✅ 完全自動化，無需手動維護賽道字典
- ✅ 基於實際加速度數據，精度更高
- ✅ 自動適應不同賽道和賽道變化
- ✅ 新增賽道無需任何配置

## 🔬 技術實作細節

### 新增方法

1. **`_get_or_calculate_acceleration()`**
   - 優先使用 FastF1 的 `Acceleration` 欄位
   - Fallback: 從 Speed 差分計算
   - NaN 處理和平滑

2. **`_find_reference_brake_endpoint()`**
   - 從最速車手全圈找加速度最小值（最大負值）
   - 返回位置和加速度數值

3. **`_find_driver_brake_endpoint()`**
   - 在參考終點±50m 範圍搜尋
   - 找到該車手的最大負加速度點

4. **`_find_brake_start_from_endpoint()`**
   - 從終點往前掃描
   - 找第一個加速度 > -1 m/s² 的點

### 程式碼統計

- **新增代碼**: ~200 行
- **移除代碼**: ~150 行（硬編碼邏輯）
- **淨增加**: ~50 行
- **編譯錯誤**: 0 個
- **執行測試**: 2 個賽道成功
