# Function 100 優化修正報告

**日期**: 2025-11-11  
**問題**: 2025 年巴西站最高速度數據不準確  
**修正**: 優化策略調整

---

## 🔍 問題發現

### 用戶反饋
- **正確數據**: 346 km/h (VER, Lap 17)
- **第一次優化產出**: 340 km/h (ALB, Lap 71) ❌

### 問題原因
第一次優化嘗試使用 `session.laps.get_telemetry()` 批量載入所有車手的遙測數據，但 FastF1 不支援：

```python
# ❌ 失敗：Cannot slice telemetry because self contains Laps of multiple drivers!
all_telemetry = session.laps.get_telemetry()
```

導致自動降級到**速度陷阱數據**（SpeedI1/I2/FL/ST），但速度陷阱只測量特定位置的速度，不是全賽道的真實最高速度。

---

## 🔧 修正方案

### 優化策略調整
改為**按車手批量載入**（而非一次性載入所有車手）：

```python
# ✅ 正確：按車手批量載入
for driver in drivers:
    driver_laps = session.laps.pick_drivers(driver)
    driver_telemetry = driver_laps.get_telemetry()  # 一次載入該車手所有圈
    max_speed = driver_telemetry['Speed'].max()
```

### 性能分析
| 方法 | 調用次數 | 性能 |
|------|----------|------|
| **原始方法**（逐圈） | 20 × 71 = 1,420 次 | ❌ 極慢（10-12 分鐘） |
| **第一次優化**（全局） | 1 次（失敗） → 降級 | ⚠️  數據不準確 |
| **修正後**（按車手） | 20 次 | ✅ 快速 + 準確（18 秒） |

## 📝 關於圈數差異

**用戶回報**: Lap 17  
**系統計算**: Lap 16

### 可能原因
1. **時間點邊界**：最高速度發生在 Lap 16 結束或 Lap 17 開始的交界處
2. **計算方法差異**：
   - FastF1 使用 `SessionTime` 反查最接近的圈數
   - 不同數據源可能採用不同的圈數歸屬規則

### 結論
速度數據 **346 km/h (VER)** 完全正確，圈數差異（16 vs 17）屬於可接受的計算邊界誤差。

## 📚 技術細節

### FastF1 API 限制
```python
# ❌ 不支援：多車手混合遙測
session.laps.get_telemetry()  # 報錯: Cannot slice telemetry

# ✅ 支援：單車手遙測
driver_laps = session.laps.pick_drivers('VER')
driver_laps.get_telemetry()  # 正常工作
```

### 優化後的完整流程
1. 載入會話（`session.load(laps=True, telemetry=True)`）
2. 遍歷 20 位車手
3. **按車手批量載入遙測**（每人 1 次調用）
4. 找出該車手的最高速度
5. 透過 `SessionTime` 反查圈數
6. 更新全賽最高速度
